El **ledger** de la org suma transacciones en **MXN** (FX fijo, hoy 20 MXN/USD). En el dashboard y en la API de créditos ves el saldo en **USD** equivalente. Cada llamada exitosa descuenta su costo del saldo.

## Tipos de movimiento

| Tipo | Signo | Cuándo |
|------|-------|--------|
| `bonus` | `+` | Bono / ajuste de crédito |
| `recharge` | `+` | Recarga Stripe confirmada |
| `consumption` | `-` | Llamada exitosa al gateway |
| `refund` | `+` | Reembolso (manual) |
| `adjustment` | `±` | Ajuste del equipo (raro) |

## `GET /v1/credits`

Compatible con el shape de OpenRouter (`data.total_credits` / `data.total_usage` en USD), más extensión `geekhub`:

```bash
curl https://api.geekhub.mx/v1/credits \
  -H "Authorization: Bearer ghub_sk_live_TU_KEY"
```

```json
{
  "data": {
    "total_credits": 25.0,
    "total_usage": 3.42
  },
  "geekhub": {
    "balance": { "usd": 25.0, "mxn": 500.0 },
    "spent_30d": { "usd": 3.42, "mxn": 68.4 },
    "api_key": {
      "name": "prod",
      "budget_limit_usd": null,
      "budget_period": null,
      "spent_usd_current_period": 0
    }
  }
}
```

`total_usage` / `spent_30d` = gasto de requests en los últimos 30 días.

## Threshold en el dashboard

| Saldo (equiv. USD) | Comportamiento |
|--------------------|----------------|
| Holgado | Servicio normal |
| Bajo | Decision card de saldo bajo en el dashboard |
| `≤ $0` | Gateway responde **`402 insufficient_balance`** |

Puedes configurar umbral y recarga automática con tarjeta guardada en [Facturación](https://app.geekhub.mx/dashboard/billing).

<Tip>
  Un cron con `GET /v1/credits` alcanza para alertar cuando el saldo cubra menos de un día de uso típico.
</Tip>

## Detalle de cada cobro

En [/dashboard/usage](https://app.geekhub.mx/dashboard/usage): modelo, tokens / unidades, costo (UI en USD), latencia, status, timestamp.

En [/dashboard/billing](https://app.geekhub.mx/dashboard/billing): movimientos (recargas, bonos, consumos) y CFDIs.

## Race conditions

El descuento es **atómico** (`consume_credit_on_request` + advisory lock por org). Requests fallidos no generan `consumption`.
